# Red Team Audit — v2 Deep Research Prompt System

**Audit date:** 2026-05-05
**Audit target:** HEAD `8615132` post-compaction
**Auditor:** Adversarial peer reviewer (general-purpose subagent)
**Verdict:** FAIL — the v2 system as-is would cause the pilot to fail again (multiple CRITICAL defects, including a slot-collision-class structural bug, gameable Tier-1 allowlists that re-open the v1 framework regression risk, and unimplemented verification chain).

## Executive summary

The v2 prompt system fixes most of v1's surface defects but carries (1) a self-corrupting "Slot reference" table in every generated file, the same class of structural bug v2's `<<<...>>>` syntax was supposed to prevent — the generator's `str.replace` clobbers the documentation cells the table is meant to *describe*; (2) systematic Tier-1 allowlist contamination across 6 of 12 topics, with topic 09's allowlist containing ZERO genuine Tier-1 Dalio sources and topics 10/11 containing only 1 of 4 — R20's enforcement is hollow on the entire Module 2 (alpha + risk-parity + stress-testing), exactly where the corpus-thinness regression v1 was rejected for is structurally guaranteed to recur; (3) an internally incoherent R20 silence-proof clause ("verbatim Dalio passage proving silence") that no model can satisfy faithfully; (4) zero scripts implementing the R17-R25 verification steps the handoff and template both claim Claude will run; and (5) the topic 04 case allowlist mixes "chronic" cases with the three named archetypes, creating an R23 / R18 collision the model cannot resolve without either catch-all violation or out-of-allowlist substitution. The handoff doc claims "topic 04 fully populated" — true only by case-count, not by archetype-classification fidelity. The pilot would fail the same way v1 did, with the same root cause but better-disguised by the new rule layer.

## Findings

### CRITICAL findings (will cause pilot to fail)

#### Finding C1: Slot-reference documentation table is corrupted in every generated file

- **File:line:** `chatgpt_audit_kit/_deepresearch_prompt_04_deleveragings.md:512-540`
- **Verbatim:** `| Slot | Source | Format |` then `` | `1.4` | registry entry `id` | string, e.g. `1.4` | ``
- **Defect:** The template's "Slot reference" table at `_deepresearch_prompt_template.md:491-503` documents slot syntax with cells like `` `<<<ID>>>` ``, `` `<<<TITLE>>>` ``, etc. The generator's `_substitute_slots` does global `text.replace("<<<ID>>>", entry["id"])` at `_deepresearch_prompt_generator.py:101-111` over the *entire* template text. Result: every `<<<NAME>>>` token inside the documentation cells is ALSO substituted, destroying the doc table. The generated 04 file has cells reading `` `1.4` ``, `` `Deleveragings` ``, full prose paragraphs of `scope_in` text inlined into a 1-row table cell (line 518), and the entire 5-line `named_components` block embedded in another cell (lines 520-525) — a malformed Markdown table.
- **Evidence:** Compare `_deepresearch_prompt_template.md:493` (`` | `<<<ID>>>` | registry entry `id` | ... | ``) with `_deepresearch_prompt_04_deleveragings.md:514` (`` | `1.4` | registry entry `id` | string, e.g. `1.4` | ``). The slot column has been replaced by the substituted value.
- **Impact:** This is the SAME class of structural bug the task warned about ("v1 used `{ID}` and the generator's str.replace hit literal `{ID}` mentions in instruction prose. v2 changed to `<<<NAME>>>` to fix that"). The `<<<NAME>>>` syntax avoids collision with example uses in instruction prose, but the slot-documentation table is itself a use of the slot tokens that should have been preserved. This bug also has a substantive consequence: the generated file's "Slot reference" section is now self-referential garbage that any human reader will trip on. While ChatGPT only sees the PROMPT block (which is unaffected), this defect proves the generator does not understand its own scope — a model could be invoked with future template changes that DO include slot tokens inside the PROMPT block as escape examples, and those would also be clobbered.
- **Fix:** Either (a) wrap the slot-reference table in a "## DO NOT SUBSTITUTE" sentinel block that the generator skips, or (b) escape the slot tokens in the doc table (e.g., `` `<<<ID>>>`{:.no-substitute} `` with a generator-side filter), or (c) move the slot reference out of the template entirely and into the template's *header comment* or a separate `_slot_reference.md` file. Simplest: in `_substitute_slots`, split the template at `## Slot reference (for the generator)` and only substitute the prefix.

#### Finding C3: R20's "silence-proof verbatim passage" requirement is logically incoherent

- **File:line:** `chatgpt_audit_kit/_deepresearch_prompt_template.md:297-303`
- **Verbatim:** "§11 must include a row containing a verbatim Dalio passage from that source proving silence on the specific gap."
- **Defect:** A verbatim quote cannot prove the *absence* of treatment of a topic elsewhere in the same source. Proving silence requires either (a) a corpus-level absence search showing zero hits for the gap-topic, or (b) a meta-claim by the author ("I do not address X in this paper"). Asking for a "verbatim Dalio passage from that source proving silence" sounds rigorous but is unsatisfiable on its face. A model will respond by either citing a passage where Dalio says something tangential and labeling it "silence proof" (gameable; meaningless), or citing a Dalio meta-statement that doesn't exist (hallucination).
- **Evidence:** R20 is the v2 hard-rule; it carries the BLOCKING tag. The phrasing repeats at template:297-303 and again at the reject-trigger list (template:449-451: "any searched Tier-1 source with fewer than 3 verbatim quotes AND no silence-proof row in §11"). The original v1 redteam's R20 sharpening (`_redteam_review_pilot_04_deleveragings.md:76`) requested "the §11 row must include a verbatim Dalio passage proving the source's silence on the specific gap" — same incoherent phrasing, inherited.
- **Impact:** A model has two paths: (a) game it ("Here is Dalio at p. X talking about Y; the absence of any mention of Z in his treatment of Y proves silence on Z" — gameable), or (b) refuse and the prompt-rejection cascades. R20 is supposed to police corpus breadth; this clause renders it gameable, which restores the v1 corpus-thinness defect by a different route.
- **Fix:** Replace silence-proof clause with a *search-trace* requirement. Specify: "§11 row must list (i) the Dalio source title + page-range searched; (ii) the exact keywords / phrases tried with the source's text-search facility, in a `Keywords tried:` field; (iii) the result count from each search ('0 hits', '3 hits — see §N body cite'); (iv) for zero-hit searches, the row constitutes the silence claim, no passage required." Also: clarify that R20's `min=N searched` requires either ≥3 quotes OR ≥3 distinct keyword searches yielding zero hits per source, NOT a verbatim passage proving absence.

#### Finding M5: R12 vs R24 conflict on smart quotes from source PDFs

- **File:line:** `chatgpt_audit_kit/_deepresearch_prompt_template.md:210-220` (R12) and `:355-361` (R24)
- **Verbatim:** R12 "Adding words inside quote-marks = rejection. Deleting punctuation inside quote-marks = rejection." R24 "The body of every `> **Dalio**` quote block MUST use plain ASCII straight quotes, not curly/smart quotes."
- **Defect:** R12 forbids modifying any character inside a quote block. R24 forbids smart quotes inside a quote block. Modern PDFs (including Dalio's economicprinciples.org renders) commonly use typographic quotes (U+201C/U+201D, U+2018/U+2019) and em-dashes (U+2014). If the source PDF uses these, R12 says copy-paste verbatim (preserving the smart character); R24 says reject for smart character.
- **Evidence:** R12 at template:215-216 explicitly prohibits modification of punctuation. R24 at template:359-361 explicitly prohibits smart quotes inside `> **Dalio**` blocks. No exception clause references the other rule.
- **Impact:** A scrupulous model retrieving from a PDF that uses curly quotes is forced to choose which rule to violate. A less-scrupulous model will silently normalize smart→straight (which is what v1's "has the be" auto-correct was) and pass R24 while creating a silent R12 violation. This re-creates the v1 failure mode.
- **Fix:** Add an exception to R24: "If the verbatim source uses smart quotes / em-dashes, preserve them and add a `[normalized for ASCII]` annotation in `_quote_audit.md`. The byte-equal check (R21) MUST be against the un-normalized source bytes." Or: redefine R24 to only ban contamination from chat-style autoformat (i.e., smart quotes in body prose where the source has straight, NOT vice versa).
